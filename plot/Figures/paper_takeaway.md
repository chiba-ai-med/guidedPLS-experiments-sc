# Paper Takeaway — guidedPLS-experiments-sc (Fig. 3 contribution)

1. **Guided-PLS works for unpaired scRNA-Seq / scATAC-Seq integration at single-cell resolution, given an informative coarse guide Z.** Primary benchmark: 10x Genomics 10k PBMC scMultiome (~10k cells, 11 cell types), with `broad_lineage` (T / B / NK / Myeloid / Other) as guide Z and `celltype` (CD4 T Naive, CD8 T Memory, CD14 Mono, ...) as held-out evaluation label. **gPLS_germlayer reaches accuracy 0.616**, beating Harmony (0.317) and Scanorama (0.476), and approaching Seurat anchor-based label transfer (0.867). ARI shows the same ranking (gPLS 0.485, vs Harmony 0.213, Scanorama 0.355, Seurat 0.735).

2. **Cell type is held out as an evaluation label throughout.** Guide Z uses only the broad lineage that one could in practice obtain from FACS-sorting or coarse marker panels. The eval label `celltype` is never used in training for any method. For PBMC, both guide and eval are derived from the same RNA clustering + marker-gene scoring, so there is no taxonomy mismatch artifact (which inflated some baselines on Organogenesis).

3. **gPLS is algorithmically constrained but competitive on both accuracy and compute.** A fair side-by-side requires noting what each method gets:
   - **Latent dimensionality**: gPLS = **5** (bounded by rank of Y = broad_lineage cardinality), Seurat = 30 (CCA), Harmony = 30 (PCA), Scanorama = 100. gPLS works in a latent space **6–20× smaller** than the baselines.
   - **Feature space**: gPLS uses **raw RNA HVGs (3,000)** and **raw ATAC peaks (~36,000 PBMC / ~64,000 Organogenesis)** with no shared coordinate. Seurat / Harmony / Scanorama all use the **Gene Activity Matrix** (~2,200 genes shared between modalities), which itself is a curated, modality-bridged feature space.
   - **Cross-modal supervision**: gPLS receives only the guide Z (broad_lineage). It never sees cross-modal cell-cell correspondences. Seurat builds explicit RNA↔ATAC anchors; Harmony and Scanorama at least share the gene space across modalities.

   Despite operating on a smaller, less curated, more weakly supervised representation, gPLS reaches accuracy 0.616 (vs Harmony 0.317, Scanorama 0.476).

   **Conceptual / integration-taxonomy note.** All four methods are addressing the same underlying *diagonal* integration problem in the Argelaguet et al. sense — different cells in different modalities, no intrinsically shared feature space, no per-cell pairing assumed at training time. The three baselines artificially *convert* the diagonal problem into a horizontal one by constructing a Gene Activity Matrix (GAM) that maps each ATAC peak to a nearby gene, so that RNA and ATAC can then be compared in a single gene-level coordinate. gPLS does **not** make that conversion; it operates on the raw peak matrix and bridges modalities through the guide Z alone. Two practical consequences follow:
   - **gPLS results are not bottlenecked by GAM quality.** Where GAM is unreliable — sparse / low-depth ATAC, organisms with poor gene annotation, datasets dominated by distal enhancers (>50 kb from target), or cell types whose regulation deviates from a simple accessibility → expression assumption (enhancer-primed developmental states, immune super-enhancer programs, dysregulated tumours) — the baselines inherit the GAM's limitations while gPLS does not. The PBMC benchmark uses well-annotated human, where the GAM advantage of baselines is at its strongest; gPLS still competes there.
   - **Cell pairing is never used.** PBMC is naturally vertical (10x scMultiome — same cells in both modalities) but is presented to all four methods as a diagonal problem: cells are renamed `_R` and `_A` so the pairing is invisible to the algorithms, and the pairing is reserved for ground-truth evaluation if needed. Organogenesis is intrinsically diagonal (separate scRNA and scATAC experiments from different individuals and labs). gPLS therefore competes fairly on both datasets under the same diagonal-integration setting.

   **Compute (Fig 3B) is no longer a trade-off as of `guidedPLS` v1.2.0.** The v1.2.0 release added native sparse-matrix support; on PBMC, gPLS wall time dropped from 469 s to **108 s** (4.3× faster) and peak memory from 21.3 GB to **4.25 GB** (4.9× lighter). The final ranking on PBMC: gPLS time 108 s is on par with Seurat (99 s) and within ~2× of the fastest method Harmony (62 s); **gPLS memory 4.25 GB is the lowest of all four methods**, beating Scanorama (5.7 GB), Seurat (7.7 GB), and Harmony (8.3 GB). The previous "implementation cost" caveat is therefore resolved — gPLS is now in the competitive band on compute while keeping its accuracy advantage over Harmony / Scanorama.

   **Benchmark scope (what is and isn't measured).** The numbers above are Snakemake `benchmark:` wall time and max-RSS for each method's main rule, measured sequentially (cores = 1) on the same machine. Scope per method:
   - gPLS: load X1/X2 (sparse `.mtx`) + Y1/Y2 → `guidedPLS()` SVD → score standardisation → kNN label transfer → write `predicted_labels.csv` + `guidedpls.RData`. **Embedding extraction to `embeddings.csv` is a separate rule (`save_gpls_embeddings`) and is not included** — it is a few seconds of metadata-join + I/O on the RData, so the exclusion is small.
   - Seurat: load `.rds` → `FindTransferAnchors` (CCA, anchor scoring) → `TransferData` → write `predicted_labels.csv` → **plus** a `RunCCA` step that is rerun specifically to extract a joint embedding for the Fig 3A UMAP comparison. The Seurat benchmark therefore includes ~one extra CCA pass that the canonical "label transfer only" workflow would not need; pure label-transfer Seurat would be measurably faster than 99 s.
   - Harmony: load `.rds` → merge → joint PCA → `RunHarmony` → kNN label transfer → write labels + harmony embeddings. Embeddings are the natural output of `RunHarmony`, so there is no separable "extra" cost.
   - Scanorama: R subprocess to dump common-gene matrices to CSV → Python load → `scanorama.correct` + `scanorama.integrate` (both intrinsic to the algorithm) → kNN label transfer → write labels + embeddings. No separable "extra" cost.

   The most notable scope asymmetry is the extra `RunCCA` in the Seurat rule — it makes Seurat look slower than a pure label-transfer Seurat would be. We leave the figure as is rather than backing the CCA out, because (i) the embedding is genuinely useful for Fig 3A and someone running the full pipeline pays this cost too, and (ii) it does not change the qualitative conclusion that the four methods are within ~2× of one another on wall time, with gPLS now lowest on memory.

4. **gPLS aligns modalities along the celltype axis, not by mixing them.** The integration footprint differs qualitatively from anchor-based methods. In nearest-neighbour modality-mixing (lower = better mixing; 100% = total separation, 50% = perfect mix), Seurat achieves 63% (it really mixes RNA and ATAC cells in latent space), but gPLS, Harmony, and Scanorama all stay at 97–99% (modalities remain visually segregated). Despite this, gPLS achieves competitive label-transfer accuracy because **same-celltype RNA and ATAC cells end up at the same coordinate along the guide-Z directions** — they do not need to overlap in space, only to be co-located along the celltype axis. This is a structurally different kind of "integration" than anchor mixing.

5. **The framework's regime of validity is set by how the guide Z stratifies the eval label.** When Y is a coarse partition that strictly refines into the celltypes you want (PBMC: broad_lineage refines into celltype subtypes), gPLS recovers strong celltype information through 5 latent dimensions. When Y is poorly aligned with celltype identity (Organogenesis: germ_layer × stage encodes anatomical position more than celltype identity, with 41 fine celltypes spread across only 9 guide bins), gPLS underperforms — best accuracy 0.164 vs Seurat 0.476. This crossover is the central methodological observation: **gPLS shines when the guide Z is a true biological prior over the celltype space**, and degrades gracefully when Y is uninformative for the eval label.

6. **gPLS hits guide-level accuracy without collapsing to it.** When PBMC predictions are collapsed to the broad_lineage axis (the same partition that gPLS used as guide Z), gPLS reaches **0.931 accuracy** — a +31.5 pp jump from its celltype-level 0.616. Seurat / Harmony / Scanorama only gain +7–9 pp from the same collapse (Seurat 0.867 → 0.955, Harmony 0.317 → 0.390, Scanorama 0.476 → 0.564). The asymmetry is informative: gPLS's errors are concentrated **within broad lineage** (e.g., predicting CD4 T Memory instead of CD4 T Naive, while staying inside the T branch), whereas the other methods make broad-axis mistakes at similar rates. **Crucially, gPLS is not merely degenerating to the guide**: if it were, celltype-level accuracy would collapse to roughly the fraction of the dominant sub-celltype per broad bin (~0.30 for "always predict CD4 T Memory inside T"), but the observed 0.616 is twice that. Sub-broad celltype structure is being preserved through the latent space, just with noise. **Practical implication for users with uncertain fine-grained labels**: when only coarse experimental labels (e.g. FACS-sortable broad lineage) are available with confidence, gPLS using that coarse guide already produces reasonable label transfer at both the coarse and fine grain. This is the everyday use case the framework is built for.

7. **Supplementary control — celltype as guide**: A reference experiment using the eval label itself as guide Z is included in the supplementary. As expected, this gives near-perfect celltype-level prediction; the value of the panel is to show that gPLS uses the guide as intended (no leakage from guide construction independent of guide content). Combined with point 6, this brackets the framework's behavior: coarse-guide → coarse-acc near 1, fine-guide → fine-acc near 1, with graceful fall-off when guide is coarser than the eval label.

8. **Fig. 3 main narrative**: gPLS as a viable integration method when (i) the modalities are unpaired, (ii) GAM-style shared-feature construction is undesired (e.g., to avoid information leak from one modality's gene activity proxy), and (iii) a coarse experimental guide Z exists. With v1.2.0 sparse support, the compute argument is no longer a caveat — gPLS delivers competitive accuracy with the lowest memory footprint and a runtime comparable to Seurat. PBMC scMultiome (Fig 3 main) shows this regime; Organogenesis (Supp) shows the boundary where celltype granularity exceeds guide rank. The Testis ArchR dataset has been dropped from the manuscript because its barcode format prevents fair baseline comparison and the explanation cost outweighs its narrative value.
